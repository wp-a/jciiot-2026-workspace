# JCIIOT 2026 可追溯工作空间设计

日期：2026-07-22

## 目标

把比赛规则、官方基线、外部技术资料、工程决策和实验结果统一放进一个私有、可复现、可审计的工作空间。任何关键结论都应能追溯到公开来源、固定版本或本地实验，而不是依赖聊天记录或个人记忆。

## 仓库边界

顶层工作空间使用独立 Git 仓库，并推送到 GitHub 私有仓库 `wp-a/jciiot-2026-workspace`。顶层仓库只保存自研文档、配置、脚本和后续合规代码。

官方基线保留为 `vendor/JCIIOT2026` 下的独立 Git checkout。外部参考项目保存在 `references/repos`，同样不进入顶层 Git 历史。顶层仓库只记录它们的公开 URL、固定 commit、许可证、用途和获取命令。

以下内容禁止进入顶层 Git：

- API key、token、cookie、`.env`；
- 模型权重、HDF5 数据、压缩资产、轨迹、日志和视频；
- 官方仓库或外部参考仓库的嵌套 `.git` 目录和完整第三方源码；
- 没有明确公开来源或需要单独授权的代码、模型和数据。

## 信息架构

### 当前状态

`STATUS.md` 是当前阶段、已完成工作、阻塞项、下一步和近期决策的唯一入口。README 负责稳定导航，不承担每日状态记录。

### 调研材料

`docs/` 保存综合结论，包括比赛简报、官方基线审计、技术地图、竞赛路线、同类仓库调研和合规要求。

`research/source-ledger.csv` 是机器可读的来源台账。每条来源记录唯一 ID、类别、标题、URL、版本或 commit、访问日期、许可证、证据等级、适配模块和采用状态。

`research/notes/` 保存需要深入阅读的项目笔记。笔记用来源 ID 命名，并区分“作者声称”“本地代码审计”和“已在本比赛复现”。

### 决策记录

`decisions/` 使用简化 ADR：背景、候选方案、决定、理由、后果、证据和复审条件。技术路线发生变化时新增记录，不覆盖旧结论。

### 实验记录

`experiments/experiment-log.csv` 继续作为实验总账。正式实验必须记录官方基线 commit、自研 commit、场景、随机种子、配置、checkpoint、轨迹、官方分数、碰撞、耗时和失败原因。

大文件放在被忽略的 `experiments/runs/`、`data/` 和 `artifacts/`，通过日志中的相对路径、哈希或外部存储位置追溯。

### 第三方合规

`THIRD_PARTY_NOTICES.md` 记录计划采用或仅供研究的第三方组件。需要授权、许可证不明或与获奖公开要求可能冲突的项目必须显式标为“禁止直接集成”或“待确认”。

## 外部项目下载策略

只下载与当前方案直接相关的公开代码：

- 直接复用候选：robomimic、PythonRobotics、py_trees；
- 规划与恢复参考：multimodal-bt-generation、KIOS；
- 数据生成参考：MimicLabs、CP-Gen；
- 系统架构参考：OK-Robot、ACT++；
- 最新创新观察：MobileManiBench、RoboMonkey；
- 同赛题诊断参考：QiShengZhao/JCIIOT2026。

下载脚本采用浅克隆并跳过 Git LFS。大型或只需架构参考的仓库使用稀疏 checkout，只取 README、许可证和关键源码目录。脚本必须可重复运行，不覆盖本地未提交修改。

同赛题 fork 只用于理解诊断方法，不能复制实现。OK-Robot 的 AnyGrasp 需要授权，禁止使用。MimicGen 及依赖它的数据生成代码存在非商业许可证边界，当前只研究方法，不进入参赛实现。

## 验证

工作空间检查脚本验证：

- 核心文档、来源台账和任务配置存在且格式正确；
- 官方基线固定在记录的 commit；
- 参考仓库与 manifest 中的 commit 一致；
- 顶层 Git 未跟踪嵌套仓库、大文件、秘密文件和实验产物；
- GitHub 远程仓库可访问且 visibility 为 `PRIVATE`。

首次初始化完成后建立基线提交和私有远程。后续每个资料更新、决策或代码变更都用小而明确的 commit 记录。
