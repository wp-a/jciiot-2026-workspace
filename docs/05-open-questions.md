# 向组委会确认的问题

以下问题会改变提交是否合规或评分是否一致，建议报名后在官方讨论区/QQ 群一次性确认，并保存答复截图和日期。

1. **最终提交截止到底是 8 月 16 日还是 9 月 1 日？** 主办方赛程写 8 月 16 日 23:59，比赛主页顶部显示 9 月 1 日关闭。
2. **评分是否以当前 `app.py` 为准？** 比赛说明写“相对初始位置移动超过 1 m”，当前代码写“相对源工位中心”，且增加了成功 `grasp_end` 门控。
3. **L5 是否必须搬运三件白色 tote？** 当前代码按三件分别计分，`task_config.json` 的单个 `object` 字段只写 center 对象。
4. **允许修改目录是否为绝对边界？** 公开 fork 的无头运行修复涉及禁止修改的 `src/robot_agent/environments/`；正式提交能否包含经说明的环境 bugfix？
5. **SOP 生成结果如何查重/判原创？** 能否读取 `task_config.json` 和 semantic map 做交叉验证；生成后是否允许人工修订，若允许需如何记录？
6. **提交阶段 GitHub 仓库能否为私有？** 新补充规则明确使用 GitHub，且获奖后全部实现代码必须公开；若评审期允许私有仓库，应向哪些评委账号授权、何时转公开？
7. **客观评测是否会使用隐藏随机种子、地图变化或对象扰动？** 这决定固定 approach pose 与泛化策略的投入比例。
8. **评测服务器的软件/硬件和运行入口是什么？** 包括 OS、CUDA、Python、是否无头、网络/API 可用性、单关时间限制和允许的模型大小。
9. **GLM 免费额度的总量、速率、有效期和评测时联网规则是什么？** 需要决定在线 VLM 与离线缓存方案。
10. **碰撞判定的忽略几何体和 warmup 参数是否会固定为仓库当前值？** 以及一次任务多次碰撞是否始终只扣一次 5 分。
11. **“不允许需要授权的代码、数据或工具”如何界定公开 API 和公开权重？** 比赛提供 GLM API 额度，但 API key、模型服务联网和评测期可用性仍需明确；同样需确认公开发布但要求注册/接受许可证的模型权重是否允许。
