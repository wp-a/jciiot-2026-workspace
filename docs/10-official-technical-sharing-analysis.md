# JCIIOT 官方技术分享研究结论（2026-07-31）

## 结论先行

官方路线不是“只让箱子移动到得分点”，而是完整的
`move -> pick_up -> move -> place_down`：先物理夹住并抬升箱体，再运输，最后在目标工位释放并稳定。

但官方 Baseline 也不是全程依靠夹爪接触动力学维持远距离运输。官方源码中的
`transport_attachment.py` 明确说明：导航脚本直接修改 Tiago 底盘 qpos，自由物体不会自然跟随，
因此在物理抓取成功后捕获箱体相对底盘的位姿，运输期间同步箱体 freejoint。

因此，任务一的推荐实现是“物理抓取门控 + 官方运输/下放约束 + 重力释放”，而不是以下两个极端：

- 不允许在抓取前或抓取失败后直接移动箱体，这会造成用户所见的“箱子飞起来”。
- 没必要坚持约 14 m 全程纯接触夹持；它与官方直接改底盘 qpos 的导航实现不相容，且已被实测证明不稳定。

训练仍然必要，但训练目标应集中在官方明确指出的薄弱环节：不同场景、箱体和初始位姿下的
`pick_up` 鲁棒性。LLM 只负责高层技能序列，不负责解决夹爪接触、摩擦和滑落。

## 官方运输机制的源码审计

官方 `transport_attachment.py` 的模块说明写明：

1. 导航通过直接编辑 Tiago 的 base qpos 移动机器人。
2. 被夹爪抓住的自由物体不会因这种直接更新而自动跟随。
3. `capture_transport_attachment` 在抓取后记录箱体相对底盘的 XY、Z、姿态和夹爪关节状态。
4. `sync_transport_attachment` 在导航时根据底盘新位姿重写箱体 freejoint，并恢复夹爪保持状态。
5. 官方 `place_object_physics` 在 attachment 生效时逐步降低箱体 `world_z`，然后
   `clear_transport_attachment`、张开夹爪并让重力完成释放。

所以官方演示可以同时满足“抓取阶段确实夹住”与“运输阶段箱体始终跟随”这两个现象。
从动力学角度，后半段是仿真运输约束，不是纯摩擦夹持；从赛事实现口径看，它是官方公开 Baseline 的组成部分。

## 对现有实验的纠偏

现有严格纯物理方案已经证明：

- 相对两侧对夹可重复实现双侧接触、约 0.135 m 抬升和 20 步保持，且零碰撞。
- 纯夹持配合直接 qpos 底盘导航时，箱体不会可靠跟随。
- inchworm 方案把连续稳定运输提高到约 0.158 m，但仍会失去一侧接触，无法覆盖任务一长距离路线。

这不是夹爪参数再调一点即可解决的问题，而是导航状态更新方式与接触动力学不连续造成的结构性限制。
继续要求 14 m 纯夹持，会把大量时间耗在官方已经用 transport attachment 绕开的仿真边界上。

## 最终推荐技术路线

### 任务一优先路线

1. **确定性导航到预抓位姿**：用场景几何和安全余量生成无碰撞路径，末端姿态对准箱体。
2. **真实抓取与抬升**：优先使用已经实测成功的相对两侧对夹控制；保留 BC 策略作为对照。
3. **严格抓取门控**：必须同时满足双侧夹持、连续保持、箱体抬升阈值、零碰撞；失败则停止，不启用运输约束。
4. **官方运输约束**：仅在门控通过后调用官方 attachment，夹爪保持闭合并维持合理的箱体相对位姿。
5. **无碰撞运输**：使用膨胀障碍、分段路径和转弯 clearance；运输中持续检查箱体-环境碰撞。
6. **约束下放与重力释放**：到达目标桌前对准，在官方 attachment 下逐步降低箱体，
   到安全释放高度后关闭 attachment、张爪并等待重力稳定；这与官方 Baseline 一致，但不宣称为纯机械臂下放。
7. **官方验收**：只接受未修改 `app.py` 与官方 scorer 输出的 `10/10`、零碰撞结果。

### 泛化训练路线

任务一满分后再扩展，不用无效的 591 MB dishwasher 示例 HDF5。该文件是 iGibson Fetch、10 维动作，
与 JCIIOT Tiago 双臂 20 维策略不兼容。

正确数据闭环是：

- 在每个官方场景中按多个机器人初始 XY/yaw、箱体位置和箱体种类采集成功抓取轨迹。
- 记录接近、闭合、抬升和短时保持的原生 Tiago 观测与 20 维动作。
- 先训练 BC-RNN 作为稳定低成本基线，再以相同训练/验证划分对照 Diffusion Policy。
- 选择依据是 held-out 成功率、零碰撞率、抬升保持率和推理时延，不按训练 loss 选模型。
- 失败恢复、抓取置信门控和导航仍由 workflow 管理，LLM 不直接生成连续控制动作。

## 任务一验收门槛

只有全部满足才称为成功：

- 抓取前没有箱体 freejoint 写入或 attachment。
- 抓取过程出现双侧接触，箱体相对桌面实际抬升并连续保持。
- attachment 只在上述门控后启用。
- 箱体离开源点超过 1 m。
- 箱体最终平面位置到目标桌中心小于 0.8 m。
- 到达安全释放高度后解除 attachment，张爪后箱体在目标桌面稳定。
- 全轨迹官方碰撞标志为零。
- 未修改禁止文件，官方 `app.py` 输出任务一 `10/10`。
- 仅在该轨迹上生成第一视角、俯视和第三视角 GIF。
